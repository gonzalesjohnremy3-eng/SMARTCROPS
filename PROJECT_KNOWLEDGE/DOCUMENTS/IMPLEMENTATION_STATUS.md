# Smart Crops (Agri Lynk) - Implementation Status & Feature Tracking Guide

This document tracks the user-accessible reality of every feature against `PROJECT_PLANNING.md`, `WEATHER_FEATURE_PLAN.md`, the PDF design specification, and `UI_UX_BLUEPRINT.md`.

**Audit date:** 2026-11-13 (UI/UX Phase 0 + Phase 1 complete; Phase 2 slices — calendar & care (1), Agri Pro quota + paywall (2), analytics instrumentation (3), Agri Shop + adaptive + realtime (4), FCM Android plumbing (5), AI provider rotation + honest failure (6) — complete)  
**Important:** A backend table, Edge Function, or test-only implementation is not a shipped feature. Statuses below describe what a farmer can actually use in the app today.

---

## 1. Summary Status Legend

- **[x] Implemented:** User-accessible end-to-end and integrated into the Flutter app.
- **[~] Partial:** UI or service exists, but the flow is incomplete, unwired, non-persistent, or placeholder-driven.
- **[B] Backend / schema only:** Migration, table, seed, or Edge Function exists with no app UI or service.
- **[T] Test-only:** Logic exists only in tests, not in production code.
- **[ ] Not implemented:** No user-accessible implementation.

## 3. Phase 1 progress notes

Phase 2 slice 1 — **personalized calendar & care** — is also implemented: the Care Plan segments Today / This Week / Preventive from a shared, unit-tested domain (`lib/features/calendar/domain/care_plan.dart`) with reason chips (overdue / weather / recent at-risk scan / routine), honest suggestions from at-risk scans with add-to-calendar, a task detail screen at `/calendar/events/:eventId` with why-now/weather/related-scan info and edit/delete, an add-task sheet, and `/scan/result`'s Add to Field Calendar action creating a follow-up task. All new strings are EN/TL/CEB via ARB. Incidental fix: `DeepLinkHandler.start()` no longer crashes the app/tests on platforms without the `app_links` plugin (e.g., Windows and widget tests).

Phase 2 slice 2 — **Agri Pro quota + paywall (prices approved)** — is implemented: a free farmer out of weekly scans (5/Mon-reset, counted from `scan_history`, queued reservations honored) is sent from Analyze to `/pro`; the paywall renders the Free plan summary, Pro features, Monthly ₱99 / Seasonal ₱499 (16% saved, pre-selected), transparent renew and cancel-anytime terms, and the quota context when entered at the weekly quota; `/pro/manage` shows plan, renewal, billing channel and cancel/restore instructions; a Profile row links to the paywall or manage screen. Entitlement is read from `user_subscriptions` via `AgriProEntitlement`; billing ships honestly unconfigured (`BillingRepository` seam) until Play Console/App Store Connect products are live, and the tester build uses `SimulatedProBilling` — no money changes hands, while the purchase path writes the same `user_subscriptions` row a real purchase would so the tester account behaves as if it were Pro (reinstalls included).

Phase 2 slice 6 — **AI provider rotation + honest failure** — is implemented: the edge function now rotates across all under-quota keys, speaks Gemini (`inline_data`) and OpenAI (`image_url`), and returns 502 with per-key detail instead of a canned diagnosis; the client no longer fabricates a 96.2% mock into scan_history. Requires redeploying the function and rebuilding the app.

Phase 2 slice 5 — **FCM Android plumbing** — is implemented: `google-services.json` (package `com.agrilynk.smartcrops`) is wired via the google-services Gradle plugin and `firebase_messaging`; device tokens upload to `device_tokens` and delete on sign-out; taps route via `routeForNotificationData` to safe existing routes. Also renamed the display name to "Smart Crops" (Android label, iOS/macOS bundle names, web/desktop titles) and normalized applicationId/bundle ID to `com.agrilynk.smartcrops` across platforms.

Phase 2 slice 4 — **Agri Shop + adaptive + realtime** — is implemented: `/shop` and `/shop/products/:productId` render the seeded partner catalog with search/rank, category chips, honest empty/error states, a partner-disclosure confirmation before any outbound merchant link, analytics (`shop_viewed`, `shop_search`, `shop_filter_changed`, `shop_product_viewed`, `partner_disclosure_viewed`, `partner_link_opened`), and a pre-filtered entry from the scan result (`/shop?q=<diagnosis>`, only when partner offers are allowed); Crops is master-detail at >=840px via the extracted `CropDetailContent`; all top-level screen bodies cap at 1120px; Supabase Realtime surfaces new advisories live; the share action now shares the diagnosis text. Requires pushing `supabase/migrations/20261113010000_enable_realtime_notifications.sql`. FCM background push still needs a Firebase project.

Phase 2 slice 3 — **analytics instrumentation** — is implemented: `lib/app/analytics/analytics.dart` (`Analytics`, `SupabaseAnalyticsSink`, `DebugAnalyticsSink`, PII-stripped envelope), a GoRouter `AnalyticsRouteObserver` for page-view events, a tap-safe `AnalyticsContext.trackEvent` helper that always no-ops when the provider is absent, and canonical-taxonomy events at the home/scan/care-plan/calendar/advisories/profile/paywall/wizard touch points. `user_id` is deliberately not sent; events now persist to `analytics_events` (flag flipped 2026-11-14 after the migration was pushed).

## 4. Maintenance and update guidelines

1. **Status reflects the farmer's experience.** Do not mark a feature `[x]` because a table, function, or test exists.
2. **Cite evidence.** Link the screen, service, migration, or test that proves the status.
3. **Update with the blueprint.** If a feature's UX changes, update `UI_UX_BLUEPRINT.md` and the relevant ADR in the same change.
